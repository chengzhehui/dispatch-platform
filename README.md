# 派工可视化平台

基于 Three.js + Vue + Vite 的独立派工交互雏形。项目拥有自己的依赖、源码、构建配置、模型和 Draco 解码器，不依赖 `three-demo` 的运行服务或文件路径。

## 启动（macOS / Windows）

### 从 GitHub 克隆后补齐资源

本仓库参考 three-demo 的大文件过滤策略，只提交代码、配置、文档、小型工人模型和本地 Draco 解码器。工程模型、生成数据、原始台账和数据库通过本地文件拷贝单独分发，不上传 GitHub，也未使用 Git LFS。**仅克隆仓库并安装依赖，尚不能展示工程模型和历史派工。**

从已有完整的 dispatch-platform 项目中，将以下目录复制到克隆目录的相同位置（macOS / Windows 均适用）：

| 目录 | 用途 | 是否运行必需 |
| --- | --- | --- |
| `public/models/uae/` | 阿联酋 ADNOC 五个单元模型，约 1.5 GB | 阿联酋界面必需 |
| `public/models/diesel-4d/` | 柴油项目模型，约 422 MB | 柴油界面必需 |
| `public/data/ep3d/` | 阿联酋 EP3D 索引和属性，约 34 MB | 阿联酋属性与焊缝交互必需 |
| `public/data/diesel-ep3d/` | 柴油 EP3D 索引和属性，约 96 MB | 柴油界面必需 |
| `public/data/diesel-history/` | 柴油日期索引与逐日记录，约 12 MB | 柴油历史回放必需 |
| `server-data/diesel-history/` | 原始工作簿及 SQLite 快照 | 仅离线核验、数据库测试需要 |

这些目录受 `.gitignore` 保护，复制不会使其进入 Git 提交。`node_modules/`、`dist/`、`artifacts/`、Python 虚拟环境和缓存同样不提交。资源补齐后运行 `npm run check:models` 检查模型完整性，再按下文启动。`npm test` 中的导出数据核验需要上述 public/data，`npm run test:history-import` 的快照核验还需要 server-data；浏览器检查需要完整模型。`npm run build` 可以在没有模型时完成，但该构建不含可运行的完整场景。

也可通过下文的离线导入脚本重新生成数据；柴油导入会复制柴油模型，阿联酋模型需将 `three-demo/public/4d-projects/uae/tileset/` 的完整内容复制到 `public/models/uae/`。three-demo 只在重新导入或复制源资源时需要，完成后本项目可独立运行。

### 安装依赖与启动服务

建议使用 Node.js 24；`.nvmrc` 已指定该版本。项目的 Node 最低兼容范围见 package.json 的 engines（与当前构建依赖一致）。从 Windows 复制到 Mac 时保留源码、package-lock.json、完整 public/ 与 server-data/，不要沿用 Windows 的 node_modules；在 Mac 上重新安装依赖，以安装适用于 Apple Silicon 或 Intel 的本机包。

在 Mac 终端进入实际项目目录：

```sh
cd "/你的路径/dispatch-platform"
npm ci
npm run dev
```

Windows 也可在项目目录执行相同 npm 命令。首次安装依赖后，日常启动只需 `npm run dev`。使用 nvm 的电脑可以先执行 `nvm install` 和 `nvm use`。

- 本机访问： http://localhost:5188
- 局域网访问：使用终端输出的 `Network` 地址，例如 `http://192.168.1.100:5188`。其他设备与 Mac 连接同一局域网，使用 Mac 的 IP，不使用其他设备自己的 localhost。
- 开发和预览服务均监听 `0.0.0.0:5188`，启用 strictPort；5188 被占用时明确报错，不会静默切换到 5189。
- 若 macOS 询问是否允许 Node.js 接收入站连接，请允许；仅本机可访问时检查系统防火墙及路由器的访客网络／设备隔离设置。

**普通启动、焊接历史回放及模型属性查看均不需要 Python、SQLite 服务或 three-demo。** 补齐本地模型和 JSON 数据后，启动不会重新导入数据库。

```sh
npm run build
npm run preview
```

`dist` 包含完整静态资源，可独立部署在站点根目录。完整模型与派工数据会使构建目录超过 2 GB。preview 也使用 5188，运行前应停止同端口的 dev 服务。

### 可选：Mac 上重新导入数据

仅重新生成数据及执行 Python 导入检查时才需要 Python 3 和 openpyxl。npm 命令在 macOS/Linux 优先使用 python3，Windows 优先使用 python，拒绝 Python 2；可用环境变量 PYTHON 指定解释器完整路径（路径中的空格和中文可保留）。

```sh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-import.txt
npm run test:history-import
# 源 three-demo 仅在重新导入时需要；路径按实际目录修改
npm run import:diesel-history -- --source ../three-demo --target .
```

也可使用 `PYTHON="/完整路径/python3" npm run test:history-import`。阿联酋属性生成入口为 `npm run import:ep3d -- --properties <属性JSON路径> --bounds <包围盒JSON路径>`。

## 柴油轻馏分项目历史派工

顶部“项目界面”可在阿联酋派工与柴油历史派工之间切换。历史界面可直接打开 http://localhost:5188/?project=diesel-4d 。选择底部日期、拖动时间轴，或播放日期回放；默认定位到 2026-09-16（52 名盖面焊工、630 道焊口，其中 50 人／596 口可定位）。时间轴覆盖 2026-03-19 至 2026-10-27，包含无作业记录的日期；空日期显示零人，不沿用上一天。

左侧按当日盖面焊工编号列人，保留 `0015` 等前导零。选择单元只筛选该单元的记录；“全部单元”跨单元去重计算人员。点击焊工可定位人物，并列出其当日工区、全部焊口及未定位记录；青色点显示该焊工的全部已定位作业点。模型中的每名焊工只出现一次，并循环显示焊接动作、弧光和火花。严格按设定日时长播放，不再自动延长。每名焊工最多展示“日时长向下取整”道已定位焊口，按台账顺序取前若干道，每口分配至少 1 秒的演示时段（包含快速行走）。例如 2 秒／天、3 道焊口只展示前 2 道，第 3 道标记“未演示”，仍保留台账、统计和定位功能。快速行走计入当前时段，必要时加速以保证按时切日。时间轴显示固定日时长和当前进度，人物不循环，完成后停在最后一道已展示焊口；连续播放到达设定日时长即进入下一天。默认行走速度 120 m/s，可选择 30／120／300 m/s。相邻日期中同一焊工从前一天停留位置走向下一天首个作业点，新出现的焊工从当日首个点开始。调整时长、行走速度或点击“重新演示当天”会从当前位置重新开始当天任务。“暂停动作”冻结行走、姿态和日进度，暂停期间不推进演示时钟。焊工视角支持跟随观察，历史界面不接受手动移动或重新派工。

数据口径：

- three-demo 的焊接源为 `焊口初始化数据-柴油轻馏分优化利用项目.xlsx`。“盖面日期”作为焊接日期，“盖面”作为盖面焊工编号；不使用打底或原盖面字段替代缺失记录。按数据 ID 去重，保留最新修改记录；无 ID 时保留源行号。多人字段按分隔符拆分并去重。
- 本次快照含 57,822 条台账，35,462 条有盖面日期，其中 1 条缺少盖面焊工。其余 35,461 条中，32,574 条关联到模型，2,887 条未定位。未定位仍计入焊工人数与焊口数，不放置虚构人物；缺盖面焊工的焊口不虚构人员。
- 优先按“单元＋管线＋最终焊口号”关联 EP3D 焊缝节点，再尝试初始焊口号。距离超过 0.25 m 的同名模型节点不猜测关联。人物位置来自关联节点的真实几何包围盒，统一转换原模型 Y-up／瓦片 Z-up 坐标。工区来自源项目工区归属表，未匹配时明确标记未分配工区。
- 台账没有日内时刻、先后顺序和工时；动画、分配时长和任务顺序只是当日作业面示意，不表示这些焊口在同一时刻真实焊接，不据此计算工时或产能。高处仍采用虚拟站位，不计算碰撞、楼梯和脚手架路径。

独立资源与数据库：

- `public/models/diesel-4d/` 完整复制 406 个本地模型文件，约 422 MB。仅将根瓦片的 refine 改为 ADD，使独立空间分支逐步出现，管道细节仍按视距加载。默认隐藏设计背景以查看工人和管道，可用顶部“设计模型”恢复设备与平台。
- `server-data/diesel-history/source-welding.xlsx` 是源台账原件拷贝；`welding.db` 是含原始字段、源行号、规范日期、盖面焊工、模型关联和工区的 SQLite 快照。原项目没有独立的焊接 SQLite 表，因此从原台账建立该快照，不把模型属性库误作焊接记录。
- `public/data/diesel-history/` 是从上述快照生成的日期索引与逐日记录；`public/data/diesel-ep3d/` 是独立 EP3D 索引及按需属性分片。运行和静态部署仅需本项目资源，不连接 three-demo 或外部 API。原始工作簿及 SQLite 留在源码项目的 server-data，不发布为静态网页资源。
- 两个项目的数据、人数和操作状态分开；历史只读界面不会覆盖阿联酋的浏览器派工记录。

需要重新导入最新源文件时，在项目目录运行（离线工具需要 Python 和 openpyxl）：

```powershell
npm run import:diesel-history -- --source ../three-demo --target .
npm run test:history-import
```

## 试用流程

1. 默认加载阿联酋ADNOC项目 213 单元，生成 12 名焊工。每个单元独立设定今日人数，范围 0–200；增加或减少只影响当前单元，其他单元人员保持原状。切换单元时人数输入框自动同步。新增人员进入当前单元预备区；编号在全项目内唯一，不复用已移除的编号。
2. 点击顶部“预备区”，靠近查看人物；鼠标左键点击人物选中，再点击模型范围内的工区地面，人物自动走到目标。
3. 审阅模式下拖动左键框选多人，Shift 点击切换加选；A 全选当前单元，Esc 返回审阅并取消选择。人员列表也可选中人物。焊工模式下 A 改为向左横移，左键改为观察视角。
4. 审阅模式采用 Navisworks 类似的键位：左键选择、中键平移、Shift＋中键旋转，右键保留给未来菜单。相机使用与 three-demo 同版本的 `camera-controls@3.1.2`，朝鼠标位置平滑缩放（`smoothTime=0.12`、`draggingSmoothTime=0.08`）。点击“全景”恢复模型视角。
5. 可设定 25/50/100 米立方体工区。选择派工楼层后，在该层的水平面派工；下拉框显示原模型绝对标高。点击“工区统计”窗口中的任意工区可定位并切到该楼层。可通过“地面标高”输入框校准当前单元地面。
6. 已选人员可返回预备区或停止移动；可全局暂停/恢复，选择 4/16/30/60 m/s。默认 16 m/s 为加速演示速度，不代表真实人员行走速度。
7. 单元列表可切换 213、27、37、38、39，仅加载当前单元模型。重复点击当前单元不重新加载、不改变相机及选择；只有“重新加载”会强制重载。其他单元人员保留，并继续移动和参与全项目统计。
8. 右上“视角控制”可切换自由审阅与焊工操控，键盘 ← / → 或面板选择人物，Esc 返回进入前的审阅相机。焊工模式默认背后 6 m 第三人称跟随，滚轮平滑拉近/拉远（0–25 m），拉近到第一人称时隐藏自身模型。“操控设置”可调整手动速度（2/4.5/8/16 m/s）、跟随距离并恢复背后视角。窄屏将视角面板放到侧栏操作区下方。
9. 点击目的地时显示 MOBA 风格移动指令特效：瞬时扩散波纹、持续脉冲圆环、旋转弧线、向内箭头和悬浮指示。标记固定在实际点击位置，移动过程中持续显示；取消选择或暂停不会清除，全部到达后消失。多人编队共享同一个指令标记，部分人员改派后，原标记继续等待原指令中剩下的人员。停止或删除人员会清理失效标记。特效按视距调整大小，并随所属单元显隐；刷新恢复未完成的移动指令标记。开启系统“减少动态效果”时保留静态指示。

### 焊缝绑定与焊接状态

213 单元支持真实 EP3D 管道和焊缝拾取。打开“焊缝与属性”，按“当前单元 → 管线 → 元件／焊缝”展开结构树。树内搜索匹配管线、元件名称／编号和焊缝号，保留父级路径；长列表分批显示，点击节点查看默认展开的 EP3D 属性，点击“定位”靠近模型；定位时会隐藏设计模型，顶部“设计模型”可恢复。选中焊缝或元件后会以蓝色和明暗变化呼吸高亮；按 three-demo 方式开启深度检测与多边形偏移，不穿透前方设备。Esc 清除焊工、焊缝及元件选择，即使搜索框获得焦点也生效，不停止已绑定作业。并将审阅相机旋转中心移到该对象；按 PageDown 或属性面板“定位选中对象”平滑定位，保留当前观察方向。焊工视角下定位只看向对象，不退出跟随或移动人物。选中一名焊工后，直接点击场景中的焊缝，或点击面板“绑定并前往焊缝”，工人会前往作业站位，到达后循环焊接。多个子几何按原 EP3D 对象 ID 联合高亮；不同节点即使焊缝号相同，也分别绑定。

焊接动作使用现有骨骼程序化叠加双臂前伸、手腕往复、低焊口屈膝，以及弧光和火花。人物、列表和统计区分待机、前往焊缝、焊接中。每个焊缝最多绑定一人，每人最多一项任务；“停止作业”、返回预备区、改派或手动操控会解除绑定。暂停冻结动作与作业计时，刷新恢复当天绑定及计时。这是可视化作业状态，不会自动完成焊缝或写入真实施工记录。

属性索引包含 70,820 个 EP3D 构件和 19,333 个焊缝节点，其中 19,327 个有定位几何。源项目目前仅有 213 单元的 EP3D 属性；27、37、38、39 保留设计模型交互，不生成虚拟焊缝。高处焊缝采用虚拟站位，工人直线前往，不模拟脚手架、碰撞和楼梯；地面以下的焊缝只允许查看属性，暂不绑定。

### 焊工操控

| 输入 | 行为 |
| --- | --- |
| W / S | 沿人物朝向前进 / 后退 |
| A / D | 左 / 右横移；斜向移动保持相同总速度 |
| 左键单击 / 按住拖动 | 单击真实焊缝派工，单击元件查看属性；拖动围绕人物观察，保留人物朝向。拖动或双键行走松开不会误派工 |
| 按住右键拖动 | 改变观察方向，同时控制人物朝向 |
| 左右键同时按住 | 沿当前鼠标控制的水平朝向前进 |
| 空格 | 平面跳跃，可在空中继续水平移动；落地后才能再次跳跃 |
| 滚轮 | 平滑调整人物相机距离，连续过渡第一 / 第三人称 |
| ← / →，Esc | 切换焊工，或退出操控返回审阅 |

默认手动速度 4.5 m/s，独立于底部“派工速度”。开始手动移动、跳跃或右键转向时，仅接管当前焊工，取消其自动目标和对应标记。观察相机或滚轮缩放不会取消自动派工。松开按键/双键后停止，窗口失焦、页面隐藏或编辑输入框时清空输入，避免人物持续误走；点击画布可恢复键盘操控。

跳跃基于人物当前脚下的水平面，高度约 1.17 m、持续约 0.72 s。逻辑位置和工区统计始终使用脚下平面坐标，跳跃仅改变显示高度；选中圈留在地面。切换人物或返回审阅时，已起跳的人物仍会落回原平面。没有模型碰撞、楼梯通行或自动楼板识别；鼠标观察使用按住拖动方式。

## 统计和坐标

- 模型原坐标为 Z 轴向上，转为 Three.js Y 轴向上并移到单元局部原点，避免大坐标影响人物拾取。地面取主要平台顶面标高而非可能包含地下构件的包围盒最低点：213 为 81.105 m、27 为 73 m、37 为 73.125 m、38/39 为 73 m。可手动调整并自动保存；预备区、地面和第一层工区均对齐到该基准。
- 根据原始单元包围盒生成立方体工区，末端立方体允许超出模型范围。派工目标约束在实际包围盒水平范围内。
- 工区编号：字母表示 Z 行、数字表示 X 列，连字符后的数字表示楼层，例如 `B2-3`。按人员实际 XYZ 坐标统计，人员穿越边界时更新人数；尚未到达的人员不会提前计入目标工区。
- 可显隐的工区统计窗口以三列网格展示当前单元所有楼层；场景网格展示所选楼层，避免多个楼层叠加遮挡模型。
- 总人数、预备区/区外人数、工区内人数均为全项目统计；移动中为独立状态计数，可与前两种位置状态重叠。
- 今日人员数量、位置、目标、所属单元及地面标高保存在浏览器 localStorage；刷新恢复，跨日期重新开始。兼容上一版已有人员记录。移动中每两秒及页面离开时保存当前位置。无后端、无多人协同。

## 模型来源与独立性

`public/models/uae/` 是从 `three-demo/public/4d-projects/uae/tileset/` 完整复制的真实文件，约 1.5 GB；`public/draco/` 为本地解码器，不需要外部 CDN。源码无跨项目 import、软链接或原项目服务接口。

模型按单元使用原始 `tileset.json` 渐进加载。设计模型保留概览 LOD，EP3D 分支随视距细化，以加载可拾取的真实焊缝。单元切换时销毁旧 TilesRenderer。

`public/data/ep3d/` 包含从源项目属性表及几何包围盒离线生成的约 36 MB 独立数据，索引按单元加载、详细属性按需分片加载。包围盒已包含原导入平移，不重复套用偏移。运行和部署不读取原项目；仅重新生成数据时需要源文件：

```powershell
npm run import:ep3d -- --properties ../three-demo/server-data/4d-projects/uae/model-properties/uae-properties.json --bounds ../three-demo/server-data/4d-projects/uae/model-properties/uae-geometry-bounds.json
```

## 当前边界

人物使用 [Quaternius Worker](https://poly.pizza/m/Yg2bQZO6Hj) 的 CC0 安全帽工人 GLB（约 1.28 MiB），调用 Idle/Walk/Run、后退及横移动画，跳跃叠加程序关节姿态和竖直轨迹。文件及预览图均位于 `public/models/workers/`，授权来源见同目录 `LICENSE-AND-ATTRIBUTION.txt`。每人独立骨骼和动画混合器，几何/材质共享，身高归一化到约 1.85 m。仅当本地人物加载失败时使用原简化人物。

移动仍为直线插值，包括跨楼层移动；尚未实现设备碰撞、楼梯路径、自动识别模型楼板、人员避让或真实施工任务流转。楼层是按立方体工区尺寸生成的派工平面，不代表模型实际楼板。
